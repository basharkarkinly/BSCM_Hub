نظم إدارة قواعد البيانات (DBMS)

قاعدة البيانات ونظام إدارتها، مستويات التصميم الثلاثة، المستخدمون، ومزايا DBMS مقابل الملفات التقليدية.

1 قاعدة البيانات ونظام إدارتها

قاعدة البيانات: مجموعة من البيانات أو المعلومات المتصلة ذات العلاقات المتبادلة، مخزّنة بطريقة نموذجية دون تكرار.

نظام إدارة قواعد البيانات (DBMS): حزمة برمجية جاهزة تمكّن من إنشاء قاعدة البيانات وإجراء التعديلات عليها، ومعالجة البيانات المخزنة للوصول إلى المعلومات المطلوبة.

الغرض الرئيسي لنظام قاعدة البيانات المحوسب: تخزين البيانات والسماح للمستخدم باسترجاعها وتحديثها حسب حاجته.

📌 ملاحظة

يتكون نظام المعلومات المؤتمت من: قاعدة البيانات + البرمجيات (DBMS) + التجهيزات المادية + المستخدمين.

📌 من أسئلة الدورات السابقة

محتويات قاعدة البيانات الحديثة (كملف Access): الجداول والاستعلامات والنماذج والتقارير معاً.

أمثلة على DBMS: Microsoft Access وSQL Server وOracle وMySQL. وتُستخدم DBMS في توصيف قواعد البيانات وإنشائها وإدخال المعطيات ومعالجتها.

2 مفاهيم قواعد البيانات الترابطية

  • الرابطة (Relation): الجدول — تتضمن مجموعة أسطر (سجلات).
  • السجل (Record): سطر واحد، ويتكون من مجموعة حقول (Fields).
  • التكامل (Integrated): توزيع بيانات النظام على عدة ملفات مع المحافظة على الترابط بينها بأقل تكرار وحشو.
  • التشارك (Shared): عنصر البيانات الواحد يُستخدم من قبل عدة مستخدمين في الوقت نفسه.

3 وظائف ولغات نظام إدارة قواعد البيانات

أهم الوظائف: تعريف الروابط، معالجة البيانات، الاستعلام، ضمان حماية البيانات ونزاهتها، ضمان استعادة البيانات، قاموس البيانات.

اللغةالاختصارالوظيفة
لغة تعريف البياناتDDLتعريف وتوصيف الملفات والسجلات والحقول والعلاقات وشروط التكامل
لغة معالجة البياناتDMLإضافة/حذف/تعديل سجلات، فتح وإغلاق ملفات، دمج وربط الملفات
لغة الاستعلامSQLاسترجاع وتصنيف وترتيب مجموعات فرعية من البيانات للإجابة عن استعلام المستخدم
📌 ملاحظة

قاموس البيانات (Data Dictionary): يمكن فهمه على أنه قاعدة بيانات خاصة بالنظام نفسه (وليست بالمستخدم) — يخزّن مواصفات كل حقل من حقول قاعدة البيانات.

4 مستويات تصميم قاعدة البيانات (الثلاثة)

المستوىالوصف
المنطقي (Logical)بناء الجداول بما يتوافق مع حاجة كل المستخدمين إجمالاً؛ تحديد البيانات المطلوب تخزينها والعلاقات بين الملفات — أهم مرحلة عند بناء قاعدة البيانات.
الفيزيائي (Physical)الأقل تجريداً — تحديد أماكن التخزين والفهارس، وصف السجلات وحجمها، تشفير البيانات، الأنواع الداخلية للبيانات.
الخارجي/المستخدم (External)مستوى المستخدم المفرد (نهائي أو مبرمج) — يتطلب لغة معالجة بيانات (DML/SQL) لإجراء العمليات على الملفات.
📌 ملاحظة

التصميم المادي (Physical Design): تحويل تراكيب البيانات من نموذج البيانات إلى ملفات باستخدام لغة توصيف البيانات (DDL) — وليس التصميم المنطقي.

5 مستخدمو قاعدة البيانات

  • مدير قاعدة البيانات (DBA): يحدد المتطلبات، يوفر الأمن والحماية، يعيد تنظيم القاعدة، يحدد صلاحيات المستخدمين.
  • مبرمجو التطبيقات: يحوّلون التصميم إلى قاعدة فعلية، يصيغون نوافذ التخاطب والتقارير والنماذج.
  • المستخدمون النهائيون: يتحاورون مع النظام عبر البرامج أو لغات كـ SQL (SELECT, INSERT, UPDATE, DELETE).
  • محلل النظم: يحدد متطلبات المستخدم ويطوّر المواصفات المطلوبة لتحديد المطلوب من قاعدة البيانات.

6 مزايا استخدام قواعد البيانات (مقابل نظم الملفات التقليدية)

  • استقلالية البرامج عن البيانات (تعديل الملفات لا يستوجب تعديل البرامج وبالعكس).
  • ندرة التكرار، أمن وسرية عالية، تكامل عالي ومتناسق.
  • سهولة الصيانة والاسترجاع، توفير نسخ احتياطية.
  • تمثيل العلاقات المعقدة بسهولة، واجهات متعددة للمستخدم.
⚠️ انتبه

مساوئ نظم الملفات التقليدية (قبل DBMS): تكرار وحشو في البيانات، الملفات تابعة لبرنامج التطبيق، صعوبة إضافة تطبيقات جديدة، الرقابة على البيانات من اختصاص البرنامج نفسه فقط.

📌 ملاحظة

لا نستخدم قاعدة بيانات إذا: كانت تكلفة الإعداد عالية نسبة لحجم المشروع، أو كانت البيانات بسيطة جداً، أو المشروع يحتاج سرعة استجابة قصوى، أو لا حاجة لبيئة متعددة المستخدمين.

7 أنواع نظم قواعد البيانات

هرمية (Hierarchical) — شبكية (Network) — ترابطية/علائقية (Relational) وهي الأكثر انتشاراً واعتماداً في السوق، وتتميز بالبساطة والمرونة وسهولة العرض. تعتمد على مفهوم الجداول والعلاقات.

🎮 لعبة: نظام الملفات التقليدي ولا DBMS؟

🧩 طابق: المستوى ↔ شو بيعمل

مفهوم DBMS ومكوّناته

نظام إدارة قواعد البيانات حزمة برمجية تمكّن المصمم من إنشاء قاعدة البيانات وتعديلها، ومعالجة بياناتها للوصول إلى المعلومات المطلوبة. يتكوّن النظام المؤتمت من: قاعدة البيانات، البرمجيات/DBMS، التجهيزات المادية، والمستخدمين.

اللغات والمستويات

العنصرالدور
DDLتعريف البنية المنطقية للملفات والجداول والعلاقات.
DMLقراءة السجلات وإضافتها وتحديثها وحذفها ودمج الملفات وإجراء المعالجات.
المستوى الخارجيمنظور المستخدم النهائي أو مبرمج التطبيقات.
المستوى المنطقيتحليل الحاجة للمعلومات وتحديد البيانات والعلاقات والتوافق والصلاحيات.
المستوى الفيزيائيأماكن التخزين والفهارس ووصف السجلات وحفظ البيانات وتشفيرها.

أدوار العاملين

  • DBA: الأمن والحماية، الاستعادة Recovery، الصلاحيات، وإعادة التنظيم وضبط الأداء.
  • محلل النظم: تحديد متطلبات المستخدم وتحويلها إلى مواصفات.
  • مبرمج التطبيقات: تحويل التصميم إلى قاعدة فعلية، التحقق من الصحة، وبناء واجهات الإدخال والإخراج والتقارير.

لماذا DBMS؟ ومتى لا نستخدمه؟

يعالج مشكلات نظام الملفات التقليدي: التكرار، تبعية الملفات للتطبيقات، بطء إضافة التطبيقات، وتشتت الرقابة. ويؤمن الاستقلالية، المشاركة، ضبط التكرار، الأمن والسرية، النسخ الاحتياطي والاستعادة، التكامل والمرونة وسهولة الصيانة.

⚠️ انتبه

قد لا يكون مناسباً إذا كانت كلفة الإعداد كبيرة مقارنة بحجم المشروع، أو كانت البيانات والتطبيقات بسيطة، أو كانت الاستجابة الفورية جداً مطلوبة، أو لا توجد بيئة متعددة المستخدمين.

الأنواع: هرمي، شبكي، وترابطي. يركّز المقرر على الترابطي لانتشاره وبساطته ومرونته.
